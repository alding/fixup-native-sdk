# App Store 审核准备

本文档是宿主 App 接入 FixupModule 后的审核准备模板。SDK 不能替宿主 App 获得预先审核或统一豁免；Apple 会分别审核每一个提交的 App。

## 一、审核备注模板

可以根据宿主 App 的实际产品名称和导航替换以下内容：

```text
审核入口：
1. 打开 App。
2. 使用以下审核账号登录：
   账号：<审核账号>
   密码：<审核密码>
3. 进入：<首页> -> <直播间> -> <装修首页入口>

功能说明：
该页面展示直播间的原生装修组件，包括图片、公告、商品、话题、导航和直播信息。
页面中的布局和内容由服务端返回配置，但只会选择 App 内置并已审核的原生组件。
服务端不会下发或执行原生代码、动态库、脚本或任意插件。

外部能力：
如审核流程触发 WebView、微信小程序、扫码或广告，请按实际情况说明触发入口和测试条件。
如果某个入口需要系统权限，请提供权限用途和允许/拒绝后的可继续路径。

测试环境：
接口环境：<生产环境或审核环境>
网络要求：<如果有特殊要求，请写明>
```

不要在审核备注中承诺 SDK 已被 Apple 单独认证，也不要隐瞒宿主 App 实际使用的广告、WebView、扫码或小程序能力。

## 二、上架前工程检查

- 宿主工程固定依赖明确的 SDK tag，不依赖开发分支。
- 归档工程使用 Release 配置，并在真实设备完成核心入口测试。
- 未登录、登录失效、接口超时、空模板和无网络时页面可以结束加载。
- 所有远程图片、网页和跳转地址都有安全失败路径。
- 远程配置只选择包内已实现的组件和动作。
- 不存在下载并执行代码、脚本、动态库或插件的逻辑。
- 宿主的隐私政策、App Store Connect 隐私标签和系统权限文案与真实行为一致。
- 宿主的广告、分析、微信和扫码能力由宿主自己完成隐私和权限申报。
- 审核账号可以在审核环境中完成从启动到原生装修页面的完整路径。

## 三、关于最低功能和重复 App 风险

接入 SDK 不等于拥有独立产品价值。宿主 App 应该有自己的品牌、内容、服务场景和用户价值，原生装修组件只是其中一项功能，不应把多个仅更换名称或图标的 App 作为同一模板重复提交。

## 四、远程配置与审核边界

允许服务端配置：

- 已实现组件的展示顺序
- 文案、图片、颜色、尺寸和主题
- 已实现跳转动作的业务参数

不允许服务端配置：

- 新的原生功能实现
- 可执行脚本或代码
- 动态加载的二进制或框架
- 绕过审核的新支付、广告或隐私采集流程

遇到未知组件时，SDK 应忽略该组件或展示安全占位状态，而不是下载新的实现。

## 五、审核后变更

涉及以下内容的变更，应重新进行宿主 App 的回归和必要的审核评估：

- 新增系统权限
- 新增广告或跟踪 SDK
- 新增微信、扫码或相册能力
- 新增远程配置可以触发的交互
- 改变用户数据收集、共享或用途
- 改变核心页面的登录、支付或跳转流程
